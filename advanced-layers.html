Advanced Layers

Two specialized layers complement the basic set from the Neural Networks page: BatchNorm2D stabilizes convolutional network training and Upsample2D rebuilds spatial resolution in decoders.

1. BatchNorm2D - Batch Normalization for Convolutions

1.1 What it does

BatchNorm2D normalizes 4-D NCHW flows [batch, C, H, W]: one mean/variance pair per channel, computed over the batch and both spatial axes. Each channel is then scaled and shifted by a learnable gamma/beta pair:

xhat = (x - mu) * rsqrt(var + eps)      // eps = 1e-5
out  = gamma * xhat + beta              // gamma init 1, beta init 0

1.2 Training vs inference statistics

  • During training, per-batch statistics are computed on the fly and fed into the graph as auxiliary placeholders; running averages are updated Java-side with momentum 0.9: running = 0.9 * running + 0.1 * batch.
  • During inference (predict(), setTraining(false)), the stored running averages are fed instead, so predictions do not depend on batch composition.
  • This mirrors Keras behavior but keeps all statistics in Java - the native graph only sees placeholder feeds.

1.3 Usage

// Insert directly after a Conv2D / DepthwiseConv2D layer,
// BEFORE the activation function:
try (Sequential net = new Sequential(Optimizer.adam(0.01f), 5L,
        new Input4D(28, 28, 1),
        new Conv2D(16, 3, 3, 1, 1, Padding.SAME),
        new BatchNorm2D(), new ReLU(),
        new MaxPool2D(2, 2, 2, 2, Padding.VALID),
        new Conv2D(32, 3, 3, 1, 1, Padding.SAME),
        new BatchNorm2D(), new ReLU(),
        new MaxPool2D(2, 2, 2, 2, Padding.VALID),
        new Flatten(),
        new Dense(128), new ReLU(),
        new Dense(10))) {
    net.fit(trainX, trainY, 15, 128, testX, testY, true);
}
Property Value / behavior
Input rank 4-D ([batch, C, H, W]); throws otherwise
Parameters gamma[C] (init ones), beta[C] (init zeros) - both trainable
Statistics axes batch × H × W per channel
Epsilon 1e-5 inside rsqrt
Running momentum 0.9 (Java-side exponential average)
1-D sibling BatchNorm1D for dense flows - same scheme, one mean/var per unit

1.4 Why bother?

  • Keeps activations centered through deep stacks so later layers see stable distributions - faster, steadier convergence.
  • Reduces sensitivity to initialization scale.
  • Mild regularization effect: each batch's noise in the normalization statistics.

2. Upsample2D - Nearest-Neighbor Upscaling

2.1 What it does

Upsample2D(scale) increases the spatial resolution of NCHW flows by nearest-neighbor replication: every input pixel becomes a scale × scale block. [B, C, H, W] -> [B, C, scale*H, scale*W]. It contains no learnable parameters - it is the decoder-side twin of MaxPool2D.

new Conv2D(8, 3, 3, 1, 1, Padding.SAME), new ReLU(),
new Upsample2D(2),                       // [B,C,H,W] -> [B,C,2H,2W]
new Conv2D(1, 3, 3, 1, 1, Padding.SAME)

2.2 Implementation notes

  • Built on TensorFlow's ResizeNearestNeighbor. TF resize ops are channels-last, so the layer wraps the op with NCHW→NHWC and NHWC→NCHW transposes internally - you always declare NCHW shapes at the layer level.
  • The resize op has gradients registered, so end-to-end backprop through upsampling works - no transposed-convolution needed.
  • scale must be > 1; Upsample2D(2) covers most decoder designs.

2.3 Typical decoder block

// Encoder (contracting):              // Decoder (expanding):
new Conv2D(8, 3, 3, 1, 1, SAME), ReLU,  ...   new Upsample2D(2),
new MaxPool2D(2,2,2,2,VALID),                 new Conv2D(4, 3, 3, 1, 1, SAME), ReLU,
new Conv2D(16, 3, 3, 1, 1, SAME), ReLU,       new Upsample2D(2),
new MaxPool2D(2,2,2,2,VALID)                  new Conv2D(1, 3, 3, 1, 1, SAME)

Each pool halves H/W in the encoder; each upsample restores it in the decoder. Mirroring pools with upsamples keeps skip-connection designs (U-Net style) shape-aligned. For a complete walkthrough of encoder/decoder thinking on small images, see the autoencoder-small-images project, which pairs this contracting/expanding idea with a latent bottleneck trained end-to-end via MSE.

3. SelfAttention - Scaled Dot-Product Attention

3.1 What it does

SelfAttention() lets every position of a sequence look at every other position. For a rank-3 flow [batch, T, D] it computes:

scores  = Q·Kᴹ / √D        [B, T, T]
weights = softmax(scores)     each row sums to 1
output  = weights·V + x      residual, shape preserved [B, T, D]

where Q = x·Wq, K = x·Wk and V = x·Wv are trainable [D,D] projections (Glorot-uniform). The weight matrix row i says how much position i should attend to every other position - long-range dependencies become one hop instead of a chain of recurrences.

try (Sequential net = new Sequential(Optimizer.adam(0.01f), 7L,
        new Input3D(T, D),          // one-hot planes or raw features
        new SelfAttention(),        // stackable - deepen pairwise mixing
        new SelfAttention(),
        new LSTM(48),               // recurrent layers still flatten after
        new Dense(classes))) { ... }

3.2 Implementation notes

  • Built from gradient-registered kernels only: Transpose → BatchMatMulV2 (broadcasts the [D,D] projections over the batch) → Softmax → AddV2 residual. No native changes.
  • The additive residual keeps the input signal available, so the layer can be stacked and inserted without shrinking the information path.
  • Checkpoint type code 31; save/load round-trips through the standard spec() mechanism (covered by SelfTest).
  • Cross-attention (encoder→decoder, Transformer-style) does not fit the single-flow Layer interface - assemble that by hand with GraphBuilder.

4. DenseND - Position-wise Dense for Any Rank

DenseND(units) applies the same linear transform at every position of a flow of ANY rank - typically the sequence flow [B, T, D]:

out[b, t, :] = x[b, t, :] · W + b     // shared W across all T positions
shape: [B,T,D] -> [B,T,units]

Unlike Flatten → Dense, which learns separate weights per position and destroys the T axis, DenseND keeps weights shared (fewer parameters, length-generalizes) and keeps the sequence structure alive for further attention/recurrence. It is the feed-forward sub-layer of Transformer blocks:

new Input3D(T, V),
new SelfAttention(),
new DenseND(64), new ReLU(),    // position-wise FFN
new LSTM(48),
new Dense(classes)

Checkpoint type code 32; save/load covered by SelfTest.

4. LayerNorm1D - Feature-Axis Normalization

xhat = (x - mean) * rsqrt(var + eps)   // mean/var over LAST axis,
out  = gamma · xhat + beta             // per position - not over batch!

Unlike BatchNorm1D, statistics depend only on the current sample's own feature vector - identical at train and inference time, no running averages. This is the normalization used inside Transformer blocks:

new Input3D(T, D),
new SelfAttention(),
new LayerNorm1D(),          // stabilize after attention
new LSTM(48), ...

Caveat worth knowing: because it normalizes per position across features, a position whose D features are all identical gets flattened to zero - place it where relative feature differences carry the signal.

5. PositionalEncoding - Order Information for Attention

PE[pos, 2i]   = sin(pos / 10000^(2i/D))
PE[pos, 2i+1] = cos(pos / 10000^(2i/D))
out = input + PE                          // [B,T,D], shape preserved

Attention is order-blind; this parameter-free layer injects each token's position so pure-attention stacks can distinguish early from late. T and D are fixed at build time, so the sinusoid table is baked into a constant tensor - zero runtime cost.

new Input3D(T, V),
new PositionalEncoding(),
new SelfAttention(),
...

6. EmbeddingND - Sequence-Preserving Embedding

new Input3D(T, 1),
new EmbeddingND(vocabSize, 16),   // output: [B, T, 16] - T axis KEPT
new LSTM(64),                     // ...or SelfAttention, GRU, DenseND...
new Dense(classes)

The original Embedding flattens its output to [B, T*embDim], which is why it could only ever feed Dense heads. EmbeddingND keeps the time axis, enabling the classic embedding → recurrent composition for the first time. Same one-hot MatMul realization and input contract as Embedding.

7. MultiHeadAttention - Parallel Attention Subspaces

new Input3D(T, D),              // D must divide evenly by heads
new PositionalEncoding(),
new MultiHeadAttention(4),      // 4 heads of D/4 dimensions each
new LayerNorm1D(),
new DenseND(64), new ReLU(),    // feed-forward sub-layer
new DenseND(D),
...

Each head runs scaled dot-product attention on its own D/heads-dimensional slice of Q/K/V, so different heads can specialize (one might track adjacency, another long-range matches). Head outputs are projected by their slice of WO and summed - mathematically identical to concat-then-project.

  • Causal variant: new MultiHeadAttention(heads, true) adds an upper-triangular -1e9 mask before softmax so position t attends only to ≤ t - decoder-style generation semantics.
  • Implementation note: heads are column slices of shared [D,D] projections; everything stays rank-3 and uses only gradient-registered kernels.
  • Checkpoint type code 36 (heads + causal flag serialized).

8. CrossAttention - Directed Attention Across Segments

Cross-attention needs TWO flows (queries from one stream, keys/values from another) but Layer.build receives a single flow. The solution: CrossAttention(queryLen) treats the FIRST queryLen positions of the sequence as the query segment and the remainder as key/value material:

// input layout: [question segment | document segment]
// T = questionLen + documentLen symbols, one-hot planes
new Input3D(questionLen + docLen, V),
new CrossAttention(questionLen),   // queries read across the boundary
new LayerNorm1D(),
new Flatten(),
new Dense(2)

Scores are [B, queryLen, T-queryLen]; output is the updated query segment [B, queryLen, D] with residual. Typical uses: match a short query against a longer context, relate two stacked sentences, retrieval-style classification. Checkpoint type code 37.

9. Layer Cheat Sheet

Layer Params Shape change Typical position
BatchNorm2D() gamma, beta (per channel) unchanged after conv, before activation
BatchNorm1D() gamma, beta (per unit) unchanged after Dense, before/after activation
Upsample2D(s) none H,W × s decoder stages between convs
SelfAttention() Wq, Wk, Wv (D×D each) unchanged [B,T,D] before LSTM/Flatten on rank-3 flows
DenseND(n) W (D×n), bias last dim D → n, rank kept position-wise FFN on sequences
LayerNorm1D() gamma, beta (per feature) unchanged Transformer-style blocks, attention stacks
PositionalEncoding() none unchanged before attention on one-hot/feature planes
EmbeddingND(v,dim) table (vocab×dim) [B,T,1] → [B,T,dim] token sequences feeding RNN/attention
MultiHeadAttention(h[, causal]) Wq/Wk/Wv/WO (D×D) unchanged [B,T,D] Transformer encoder/decoder blocks
CrossAttention(qLen) Wq/Wk/Wv/WO (D×D) [B,T,D] → [B,qLen,D] query-segment vs context matching
MaxPool2D(...) none H,W reduced encoder stages between convs
