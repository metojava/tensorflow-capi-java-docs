Natural Language Processing

This page covers the complete NLP toolbox of the library: the text pipeline, the Embedding layer, the recurrent family (RNN, LSTM, GRU) down to the actual gate equations, and how to assemble an encoder–decoder model despite the API's constraints.

1. The Text Pipeline

Every NLP project here follows five steps - all plain Java, no tokenizers to download:

// 1. tokenize: lowercase, strip punctuation, split on whitespace
List<String> tokens = List.of(clean.split("\\s+"));

// 2. vocabulary built on TRAINING texts only (leakage hygiene!)
Map<String, Integer> vocab = new HashMap<>();
vocab.put("<UNK>", 0);          // unknown words
vocab.put("<PAD>", 1);          // padding slot
// ...then corpus words by descending frequency: 2, 3, 4...

Special tokens: only <UNK> and <PAD> are reserved by convention - the library needs nothing else because its models read fixed-length windows and classify or transduce. Tasks that want more markers simply extend the block before corpus words (<BOS>=2, <EOS>=3, real words from 4 on); layers treat them as ordinary ids.

Token Typical id What it means / when it appears
<UNK> 0 Unknown word. Any token that is not in the training vocabulary maps here - guarantees every word gets a valid id even when new words show up at test time.
<PAD> 1 Padding. Fills the tail of shorter sequences so every sample has exactly T positions - tensors must be rectangular.
<BOS> 2 (optional) Begin of sequence. Start symbol fed before the first real token - needed by step-by-step decoders that must generate a first output from something.
<EOS> 3 (optional) End of sequence. Marks where a sequence should stop - used when decoding variable-length outputs instead of fixed T.
corpus words next ids upward Real vocabulary entries assigned by descending frequency; the id doubles as the embedding row / one-hot column index for that word. 
// 3-4. encode to ids, truncate or right-pad to fixed length T
int[] ids = new int[T];
Arrays.fill(ids, PAD);
for (int t = 0; t < Math.min(tokens.size(), T); t++)
    ids[t] = vocab.getOrDefault(tokens.get(t), UNK);

// 5. feed as floats - the layers read token ids from float arrays
float[] x = new float[sentences * T];
x[row * T + t] = ids[t];

Worked examples: Tutorial 7 (sentiment) and Tutorial 13 (news topics).

2. Embedding Layers

new Input3D(T, 1),           // token ids as floats, one per step
new Embedding(vocabSize, 16) // flattened:  [B, T*16] - feeds Dense heads
new EmbeddingND(vocab, 16)   // kept: [B, T, 16] - feeds LSTM/attention
  • Mechanics: the lookup is realized as a one-hot MatMul (onehot(ids) · E) instead of GatherV2, chosen because its gradient is a dense tensor that the generic TF_AddGradients fetch path handles without IndexedSlices conversion.
  • Two output flavors: the classic Embedding flattens to [batch, T*embDim] (bag-of-embeddings for Dense heads); EmbeddingND keeps [batch, T, embDim] so embeddings can finally feed recurrent and attention layers directly.

3. The Recurrent Family

All three layers consume a rank-3 flow [batch, T, D] declared by Input3D(T, D), are unrolled over the fixed T inside the graph, train through native BPTT (TF autodiff across the unroll), and emit the flattened states of every time step: [batch, T*H].

3.1 Vanilla RNN

h[t] = tanh(x[t]·Wx + h[t-1]·Wh + b)

One-line recurrence - great for teaching, but gradients vanish over long T, so prefer LSTM/GRU for anything real.

3.2 LSTM (Long Short-Term Memory)

An LSTM keeps two things per step: the exposed state h[t] and a cell state c[t] acting as long-term memory. Three sigmoid gates decide what to forget, write and reveal:

a = x[t]·W + h[t-1]·U + b        // W:[D,4H]  U:[H,4H]  b:[4H]
                                  // one big matmul, then carved into quarters
f = sigmoid(a[0:H])               // FORGET gate: keep old memory?
i = sigmoid(a[H:2H])              // INPUT gate:  write new memory?
o = sigmoid(a[2H:3H])             // OUTPUT gate: expose how much?
g = tanh(a[3H:4H])                // candidate content

c[t] = f ∈ c[t-1] + i ∈ g       // cell state = remembered + new
h[t] = o ∈ tanh(c[t])             // exposed state
  • The additive cell path (c[t-1] × f) lets gradients flow across many steps without vanishing - this is what makes LSTMs able to learn long-range dependencies.
  • Usage: new Input3D(T, D) → new LSTM(H) → Dense head.
  • Cost: four H-wide gate computations per step; roughly 4× a vanilla RNN of the same H.

3.3 GRU (Gated Recurrent Unit)

z[t] = sigmoid(x·Wz + h'·Uz + bz)      // UPDATE gate
r[t] = sigmoid(x·Wr + h'·Ur + br)      // RESET gate
c[t] = tanh(x·Wc + (r ∈ h')·Uc + bc)  // candidate

h[t] = (1 - z) ∈ h' + z ∈ c[t]         // blend old and new

No separate cell state, two gates instead of three, ~25% fewer parameters than an LSTM of equal H. Rule of thumb: try GRU first on small/medium data; switch to LSTM only if quality lags.

3.4 Choosing the input encoding

Encoding Flow Pros / cons
Token ids + Embedding Input3D(T,1) Compact, learned vectors - but output is flattened, so recurrent layers can't follow it.
One-hot token planes Input3D(T,V) Feeds RNN/LSTM/GRU directly; V× more floats per sample - fine up to a few thousand vocab entries.
Raw features per step Input3D(T,D), D small Time series / sensor windows (e.g. airline-lstm).

4. Building an Encoder–Decoder

A classic seq2seq has an encoder reading the source sequence and a decoder emitting a target sequence. Two honest ways to get that behavior with this API:

4.1 Pattern A - single-model transducer (recommended)

The LSTM acts as the encoder; a linear Dense(T*V) head produces the ENTIRE target sequence at once as flat scores, decoded by per-step argmax. Trained with Regressor because targets are float one-hot planes, not class ids:

// task example: reverse a digit sequence (T=8, V=10)
try (Regressor net = new Regressor(Optimizer.adam(0.01f), 42L,
        new Input3D(8, 10),                 // source one-hot planes
        new LSTM(48),                       // encoder
        new Dense(8 * 10))) {               // dense decoder head

    net.setShuffleSeed(42L);
    net.fit(trainX, trainY, 120, 32);       // trainY: reversed one-hot flats

    float[] out = net.predict(testX);       // [rows, 80] scores
    // decode: argmax over each block of V
}

This exact model was verified end-to-end: after 120 epochs it reverses unseen digit sequences with 100% exact-sequence accuracy:

input    : 5 9 0 2 8 0 8 2
target   : 2 8 0 8 2 0 9 5
predicted: 2 8 0 8 2 0 9 5

Works whenever the target length is fixed (reversal, sorting short sequences, normalization maps, slot-filling). The dense decoder ignores target-side order during decoding - each output position is produced independently - so pure generation tasks need Pattern B or more layers than this API currently offers.

4.2 Pattern B - two stages connected through Java

// stage 1: encoder compresses variable text into latent codes
try (Regressor enc = new Regressor(adam, seed,
        new Input3D(T, V), new LSTM(H),
        new Dense(LATENT))) { /* train autoencoder-style first */ }

// stage 2: decoder predicts the next item from latent + position
try (Regressor dec = new Regressor(adam, seed,
        new Input(LATENT + CONTEXT), new Dense(...), new ReLU(),
        new Dense(V))) { /* train on teacher-forced pairs */ }

The handoff happens in Java: run the encoder, copy its output into the decoder's input rows. Because gradients do not flow across the boundary, train stage 1 reconstruction-first (autoencoder objective), then freeze it and fit stage 2 - the same two-phase idea as layer freezing.

4.3 What is NOT possible today

  • Self-attention IS available: the SelfAttention layer mixes positions pairwise on any [B,T,D] flow - place it before the recurrent or flatten stage. What remains out of reach:
  • Cross-attention between encoder and decoder states - two flows, but Layer.build receives one; assemble it by hand with GraphBuilder.
  • LSTM hidden/cell states are internal to the graph - they cannot be passed between two models, hence the Java-side handoff above.
  • No pretrained model loading (no SavedModel import of BERT/GPT embeddings) - everything trains from scratch.

5. NLP Task Cheat Sheet

Task Architecture Example

6. Practical Tips

  • Keep training rows a multiple of the batch size - packed batch buffers assume uniform shapes.
  • Start Adam at 0.01, add EarlyStopping.valLoss; recurrent nets plateau visibly.
  • One-hot planes blow up quickly: V=2k tokens × T=30 steps × batch 32 is already ~8 MB per batch - trim the vocabulary before widening the net.
  • For classification heads remember the last layer is Dense(numClasses) - cross-entropy applies softmax internally; don't add a Softmax layer.
