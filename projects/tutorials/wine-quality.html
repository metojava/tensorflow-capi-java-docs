Tutorial 5 - Red Wine Quality Classification

Project Overview

The UCI red-wine-quality dataset is the classic “messy real data” project: 1,599 Portuguese vinho verde wines, 11 physicochemical measurements each, and a human-assigned quality score from 3 to 8. It introduces two challenges the iris tutorial skipped - a semicolon-separated CSV with quoted headers, and severe class imbalance. The network also gains regularization layers (BatchNorm1D and Dropout).

The Dataset and Label Remapping

The CSV ships with the project at src/main/resources/data/winequality-red.csv. Columns are separated by semicolons and the header names are quoted:

"fixed acidity";"volatile acidity";"citric acid";"residual sugar";
"chlorides";"free sulfur dioxide";"total sulfur dioxide";"density";
"pH";"sulphates";"alcohol";"quality"
7.4;0.7;0;1.9;0.076;11;34;0.9978;3.51;0.56;9.4;5

All 11 measurement columns are inputs; the integer quality score becomes the label after remapping into three bands:

Raw qualityBandCount (of 1599)
≤ 40 = low63 (~4%)
5 - 61 = medium1,319 (~82%)
≥ 72 = high217 (~14%)
// parse row -> quality int -> band
int quality = Integer.parseInt(p[FEATURES].trim());
y[i] = quality <= 4 ? 0 : (quality <= 6 ? 1 : 2);

Collapsing ten sparse scores into three bands gives each class enough examples to learn from - predicting raw scores 3..8 would leave classes with fewer than 20 samples.

Pipeline

  1. Seeded shuffle + 70/30 split - 1,120 train / 479 test rows, shuffled with seed 42 so every run is reproducible.
  2. Z-score standardization using training-set means and stds only; the test set is transformed with those same statistics. Total sulfur dioxide spans up to ~289 while density hovers near 0.99 - without scaling, one feature dominates the gradients.

Model Architecture

Input(11)
  └─ Dense(32), ReLU       wider first layer for 11 correlated features
      BatchNorm1D()          normalizes activations between layers
      Dropout(0.2)           randomly zeroes 20% of units during training
Dense(16), ReLU              narrower second layer
Dense(3)                     output: low / medium / high scores
try (Sequential net = new Sequential(Optimizer.adam(0.005f),
        new Input(11),
        new Dense(32), new ReLU(), new BatchNorm1D(), new Dropout(0.2f),
        new Dense(16), new ReLU(),
        new Dense(3))) {

    net.fit(trainX, trainY, 120, 32, testX, testY, true);
}
  • BatchNorm1D re-centers and re-scales each hidden activation across the mini-batch, stabilizing training and letting the slightly-lower learning rate (0.005) converge smoothly.
  • Dropout(0.2) fights overfitting: with only ~1,100 training rows the network can memorize them quickly. At inference time dropout is disabled automatically (setTraining(false) inside evaluation).

Evaluation: Why Accuracy Lies Here

A naive model that predicts “medium” for every wine scores ~82% accuracy while being useless. Our trained network reaches about 82% too - so did we learn anything? The confusion matrix and per-class report answer that:

Confusion matrix (rows = true label):
             0     1     2
  0          3    14     1      low: mostly swallowed by 'medium'
  1          4   357    32      medium: strong
  2          0    37    32      high: found less than half

Per-class recall:  low 0.17 | medium 0.91 | high 0.46

Reading it like an imbalanced-data practitioner:

  • Medium recall (0.91) confirms the bulk behavior - but this class is 82% of the data, so high accuracy here was nearly free.
  • High recall (0.46) is the meaningful result: the network finds genuinely good wines at roughly double the 14% base rate, at the cost of some false positives.
  • Low recall (0.17) is weakest because only 63 low wines exist in total - 44 landed in the training split. With so few positive examples, the model rationally defaults to “medium” when unsure.

Typical remedies for such skew: class-weighted loss, oversampling the minority bands, or threshold tuning on predicted probabilities - all good exercises below.

Exercises

  1. Remove Dropout and compare train vs validation loss - how much sooner does it overfit?
  2. Duplicate low-band rows 4× in the training set (simple oversampling). What happens to low-class recall?
  3. Merge low+medium into a binary task (fine vs not-fine). Does accuracy become more or less honest?
  4. Raise dropout to 0.4 and lower epochs - plot val_acc curves for both settings.
