Tutorial 15 - Sequence Transducer (Reverse & Sort)

Project Overview

This is the full encoder–decoder showcase promised by the NLP page's Pattern A: one model reads a digit sequence and writes out a TRANSFORMED sequence. Better still, it performs two different tasks - selected by a control token in the first input position:

[REV, 5,7,1,9,2,9] -> [REV, 9,2,9,1,7,5]   // reverse
[SRT, 3,3,7,8,7,6] -> [SRT, 3,3,6,7,7,8]   // sort ascending

The model is never told the rule - it must infer both transformations from paired examples and use the control token to decide which one to apply.

Data Layout

PropertyValue
Alphabet V12 symbols: digits 0..9, REV=10, SORT=11
Sequence T7 = 1 control token + 6 payload digits
Pairs1,600 seeded pairs (772 reverse / 823 sort), split 1,280 / 320 via Datasets.trainTestSplit
Encodingone-hot planes per position - each sample is a 7×12 float matrix
Targetssame layout for the transformed sequence - flat float planes (that's why the trainer is a Regressor)

The Model

try (Regressor net = new Regressor(Optimizer.adam(0.01f), 42L,
        new Input3D(T, V),
        new LSTM(96),               // encoder: reads task token + digits
        new Dense(T * V))) {        // decoder head: all positions at once

    net.setShuffleSeed(42L);
    EarlyStopping es = EarlyStopping.valLoss(25, true);
    net.fit(trainX, trainY, epochs, 32, testX, testY, true, es);
}

Decoding simply takes the argmax of each consecutive block of V outputs. There is no feedback loop: every output position is produced from the encoded input alone.

Evaluation

ran 250/250 epochs - best val MSE 0.003934 at epoch 246
digit accuracy : 0.9911
exact REVERSE  : 1.0000 (156/156)
exact SORT     : 0.9146 (150/164)

REVERSE input=[REV,5,7,1,9,2,9] target=9 2 9 1 7 5 predicted=9 2 9 1 7 5
SORT    input=[SRT,3,3,7,8,7,6] target=3 3 6 7 7 8 predicted=3 3 6 7 7 8

The contrast between tasks is the lesson: reversal is a positional mapping - output position t always copies input position 6-t, which an LSTM memorizes perfectly. Sorting is a global rearrangement - every output depends on comparing ALL inputs, so it converges slower and plateaus around 91% exact sequences (99% of individual digits are still placed correctly). Task conditioning works cleanly: zero cross-talk between REV and SRT in the confusion.

Exercises

  1. Add a third control token, e.g. DEDUP that removes repeated digits - does the shared encoder still handle three behaviors?
  2. Increase payload length back to 8 and retrain - how far does SORT accuracy fall while REVERSE stays perfect?
  3. Remove the control token and train separate models per task; compare total parameters and accuracy against the shared conditioned model.
  4. Raise LSTM(96) to LSTM(128) - how much does SORT benefit?
  5. Feed a REV example whose payload happens to be sorted already - can you catch the model "copying" instead of transforming?
