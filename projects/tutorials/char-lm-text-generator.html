Tutorial 14 - Character-Level Language Model

Project Overview

This project trains the library's first generative model: a tiny character-level language model. It reads a window of 16 characters and predicts which character comes next - a plain classification problem whose side effect is text generation: after training you feed a seed, sample the predicted distribution, append the sampled character and repeat. The model then writes new headline-like text, one character at a time.

Corpus and Windows

A seeded generator produces 1,200 headline-style lines from a mixed keyword/filler vocabulary - 42,551 characters over a 29-symbol alphabet (letters, space, period, newline). The corpus is chopped into sliding windows:

window (T=16 chars): "the blizzard.he"
label (next char):   'a'
  • stride 4 between windows keeps the dataset overlapping but diverse: 10,560 windows total
  • seeded Datasets.trainTestSplit(w, 0.2, 7L); the train half is trimmed to an exact multiple of batch 128 - 8,448 train / 2,112 test windows
  • characters enter as one-hot planes: Input3D(16, 29)

The Model

try (Sequential net = new Sequential(Optimizer.adam(0.01f), 42L,
        new Input3D(T, v),          // 16 one-hot characters
        new LSTM(48),               // reads the window left to right
        new Dense(v))) {            // next-char logits over 29 symbols

    net.setShuffleSeed(42L);
    EarlyStopping es = EarlyStopping.valLoss(8, true);
    net.fit(trainX, trainY, epochs, 128, testX, testY, true, es);
}

Note what this really is: an ordinary classifier whose classes are characters. Nothing about the model is special - the magic is in how the dataset is sliced and how predictions are consumed.

Evaluation

ran 13/40 epochs - best val loss 0.9818 at epoch 5
next-char accuracy: 0.6671

67% may look low until you remember how unpredictable text is: given "the blizzard.he", many continuations are legal. The structure the model DID learn is visible in what it writes - word-like chunks, real vocabulary, periods and line breaks in the right places. Early stopping fires at epoch 13 because the validation curve flattens quickly on a templated corpus.

Generation (The Payoff)

Sampling uses temperature: weights pc1/temp are renormalized and a character is drawn. temp < 1 sharpens toward the argmax, temp > 1 gets creative. At temp 0.8 the seeded model continues "the blizzard.he" with:

"the blizzard.heatwave coach.
storm the.bin warns.earnings."

Sentence boundaries, word shapes and topic words all emerge from 16 characters of context - no grammar rules, just statistics learned by the LSTM.

Exercises

  1. Raise temperature to 1.3 and to 0.3 - characterize the output of each extreme.
  2. Increase T to 32 - does longer context improve coherence or just training time?
  3. Swap LSTM(48) for GRU(48) - compare next-char accuracy per epoch of training.
  4. Generate from a nonsense seed like "zzz qqq xxx " - how does the model recover?
  5. Add a second corpus (e.g. the translator's Kavish lines) and check whether the model can imitate either style.
