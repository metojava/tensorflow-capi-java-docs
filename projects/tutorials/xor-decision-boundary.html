Tutorial 2 - The XOR Problem and Decision Boundaries

Project Overview

The XOR (exclusive-or) problem is the tiny dataset that famously stalled neural network research in 1969: a single-layer perceptron provably cannot learn it. In this project we generate noisy 2-D XOR data, train a one-hidden-layer MLP that solves it easily, and visualize the learned decision surface with JFreeChart.

Why a Single-Layer Perceptron Fails XOR

A perceptron computes a weighted sum of its inputs and fires when it exceeds a threshold - geometrically, that is a single straight line cutting the plane. Everything on one side is class 1, everything on the other side is class 0.

XOR labels the four corners of the square:

x₁x₂x₁⊕x₂
-1-10 (same signs)
-1+11 (opposite signs)
+1-11 (opposite signs)
+1+10 (same signs)

No single line can put the two white corners together while excluding the two black corners - they sit diagonally opposite each other. Formally, the classes are not linearly separable, so any linear model tops out at 50% here no matter how long you train it.

The Fix: A Hidden Layer + Non-Linearity

One hidden layer of non-linear units lets the network build features that a straight line cannot express. With Tanh activations, each hidden neuron learns its own line and the output layer combines those lines into curves. Geometrically, the network learns an intermediate representation such as “x·y > 0?”, which is exactly the XOR rule:

Input(2)
  └─ Dense(8), Tanh     hidden layer: bends the space
Dense(2)                   output layer: class scores
try (Sequential net = new Sequential(Optimizer.adam(0.03f),
        new Input(2),
        new Dense(8), new Tanh(),
        new Dense(2))) {

    History h = net.fit(trainX, trainY, 300, 32, valX, valY, true);
}

We use a relatively high learning rate (0.03) because the problem is small and smooth; Adam adapts step sizes per weight, so training converges within tens of epochs.

Noisy Synthetic Data

Real problems always have noise, so we add ~8% label flips to 400 points sampled uniformly from [-1,1]². The rule is simple: label = sign(x·y) > 0 ? 1 : 0, then flip randomly. This caps achievable accuracy near 92% - if the trained model hits ~90%, it has learned the true pattern rather than memorizing the noise. Because the generator uses a fixed seed, every run reproduces the same dataset.

Visualizing the Decision Surface

After training, the program asks the network for a prediction at every point of a 100×100 grid covering the plane - all 10,000 grid cells go through net.predict() in a single batched forward pass:

float[] grid = new float[GRID * GRID * 2];   // [x,y] pairs
float[] probs = net.predict(grid);           // [10000][2] probabilities
// color each cell by argmax(probs[i], i+1)

JFreeChart renders the result as a scatter plot (XYPlot with an XYLineAndShapeRenderer(false, true)): pastel blue squares mark predicted class 0 territory, pastel salmon marks class 1, and the original 400 points are overlaid as large opaque circles. Reading the chart:

  • The boundary between the colored regions is a saddle / hourglass shape, not a line - visual proof that the hidden layer bent the space.
  • Miscolored circles are the injected label noise; they live inside the wrong region because their labels were deliberately flipped.
  • The boundary is softest along the diagonals where the data is densest - exactly where the network had to make fine distinctions.

This follows the same JFreeChart pattern used throughout these projects; see the JFreeChart Integration page for API details.

Expected Output

Generated 400 noisy XOR points (~8% label flips)
Epoch 1/300 - loss: 0.7655 ...
...
Final: train loss 0.02 | val acc 0.887
Accuracy on all 400 points: 0.910 (364/400)

~91% accuracy against a ~92% noise ceiling means the network recovered the underlying XOR function almost perfectly. Training loss falls from ~0.77 toward ~0.02 while validation accuracy plateaus once only the noise remains unexplainable.

Exercises

  1. Delete the Dense(8), Tanh() layers so the model is Input(2), Dense(2). How does accuracy cap out? Why?
  2. Swap Tanh for ReLU - compare the shape of the learned boundary in the chart.
  3. Raise NOISE_RATE to 0.15 and watch the boundary get smoother - the network refuses to chase extreme noise.
  4. Increase the grid to 200×200 - does the boundary look sharper or just slower to compute?
