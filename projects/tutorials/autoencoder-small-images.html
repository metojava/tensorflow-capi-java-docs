Tutorial 12 - Autoencoder for Small Images

Project Overview

An autoencoder squeezes each input through a narrow latent code and then reconstructs it. There are no class labels at all: the network's target is the input itself. That makes it a regression problem in disguise - which is why this project trains the library's Regressor on flattened pixel values instead of a classifier. The twist added here is denoising: the network sees corrupted inputs but is graded against clean targets, so it must learn what patterns should look like.

Synthetic Image Dataset

The seeded generator (seed 42) draws 1,280 images of 12×12 grayscale pixels from three pattern families, with random ±1 pixel jitter and light sensor noise:

PatternDescription
crossdiagonal X across the canvas (brightness 0.95)
boxrectangle outline rows/cols 2..9 (0.9)
discfilled circle of radius ~3.2 centered mid-canvas (0.85)

All pixels sit on a dim 0.08 background; per-pixel Gaussian noise (σ = 0.05) simulates sensor grain. Everything is clamped to [0, 1]. A seeded Datasets.trainTestSplit(1280, 0.3, 7L) produces 896 train / 384 test images (sizes chosen as multiples of batch 32).

Denoising Setup

float[] trainNoisy = addNoise(trainClean, 0.25f, 123L);
float[] testNoisy  = addNoise(testClean,  0.25f, 124L);
...
net.fit(trainNoisy, trainClean, epochs, 32,
        testNoisy, testClean, true, es);   // noisy in, clean out
  • Inputs are corrupted with heavier noise (σ = 0.25) than the generator ever used.
  • Targets stay clean, so the only way to score well is to recover structure and drop the noise.
  • The same trained weights give you both skills: feed them clean images for plain reconstruction, noisy ones for denoising.

The Hourglass Network

try (Regressor net = new Regressor(opt, 42L,
        new Input(144),
        new Dense(64), new BatchNorm1D(), new ReLU(),
        new Dense(24), new ReLU(),                 // latent code
        new Dense(64), new BatchNorm1D(), new ReLU(),
        new Dense(144))) {                         // linear output
input 144 px --> 64 --> 24 (latent!) --> 64 --> 144 px
       encoder ~6x compression ^        ^ decoder mirror
  • Bottleneck of 24 units: 144 pixels must pass through 24 numbers - a 6× compression that forces the net to learn pattern prototypes rather than copy pixels.
  • BatchNorm1D between Dense and ReLU keeps the hidden activations standardized while training (batch stats) and uses running averages at inference - see Training Features and Advanced Layers.
  • Linear output head (Dense(144), no activation): reconstruction is unbounded regression; squashing through a sigmoid would fight the MSE gradient near saturation.
  • No weight decay here - unlike price prediction, reconstruction favors unshrunk weights; gradient clipping stays as a safety net (opt.setGradClipNorm(5f)).

Training Loop Details

  • Cosine LR schedule: LrSchedule.cosine(epochs, 0.05f).
  • EarlyStopping.valLoss(15, true) monitors validation MSE computed on noisy inputs vs clean targets - exactly the skill we care about. In the default run it stops at epoch 90 (best val MSE 0.00879 at epoch 75) out of a 150-epoch budget.
  • net.setTraining(false) before evaluation switches BatchNorm layers to their running statistics.

Exercises

  1. Shrink the latent to 8 units - at what point do the three patterns blur into one another?
  2. Raise the corruption σ to 0.4. Where does denoising RMSE cross the reconstruct RMSE?
  3. Remove both BatchNorm1D layers and compare the val-loss curve shape and final PSNR.
  4. Train without noise (plain autoencoder) and verify the model no longer removes noise at test time - denoising must be part of the training objective.
  5. Add a fourth pattern family of your own design; does the latent bottleneck still separate all four cleanly?
  6. Use the 24-D latent codes as features for a small classifier that predicts the pattern type - how accurate is it compared to classifying raw pixels?
