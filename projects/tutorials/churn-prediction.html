Tutorial 10 - Telecom Customer Churn Prediction

Project Overview

Predict whether a telecom customer will cancel their contract (churns) or stay (stays). Churn is the classic business ML problem: retaining an existing subscriber is far cheaper than acquiring a new one, so the model's job is to produce a ranked risk list the retention team can act on. The dataset is synthetic (seed 21, 2,000 customers) generated from a hidden sigmoid formula plus label noise - so we know the ground truth and can verify the network rediscovers it.

The Dataset and the Hidden Formula

Each customer carries five raw fields:

FieldRange / valuesType
tenureMonths1..72numeric
monthlyCharges$20..$120numeric
contract0 month / 1 one-yr / 2 two-yrcategorical
techSupport0/1binary flag
streaming0/1binary flag

The label is drawn Bernoulli from a noisy churn probability:

p = sigmoid(0.04*(charges-60) - 0.05*tenure
            + 0.9*(contract==month-to-month)
            - 0.6*techSupport + 0.3*streaming - 2.2) + small noise
label = random() < p ? CHURN : STAY

Reading the coefficients teaches intuition: each extra month of tenure reduces risk, high monthly charges raise it, being off a lock-in contract is a big risk factor (+0.9), while having tech support subscribed protects (-0.6). Only ~10% of customers churn - another imbalanced problem.

One-Hot Encoding Rationale

The contract column holds categories {0,1,2}. Feeding it to the network as a single number would assert false ordinality: the model would treat two-year (2) as "more than" month-to-month (0) and interpolate across meaningless orderings. One-hot encoding gives each category its own weight:

contract=0 -> [1, 0, 0]      "free to leave"     gets weight w_month
contract=1 -> [0, 1, 0]      one-year contract   gets weight w_1yr
contract=2 -> [0, 0, 1]      two-year contract   gets weight w_2yr

Binary flags already are 0/1 and stay as-is. Numeric columns get z-scored with training-set statistics. The final input vector has 2 + 3 + 2 = 7 features:

[tenureStd, chargesStd, isMonth, is1yr, is2yr, techSupport, streaming]

A Mixed Feature Pipeline

Real tabular data always mixes scales and types, so preparation must be per-column-type:

  1. Numerics - standardize with train stats, reuse on test (and on new customers at prediction time via the same mean/std).
  2. Categoricals - one-hot; never rescale a one-hot column, it would distort its meaning.
  3. Flags - pass through unchanged.

The project builds every row through one encodeStandardized(...) helper so training data, test data and the demo predictions at the end share identical encoding logic - the single most common source of silent bugs in feature pipelines.

Model Architecture and Training

try (Sequential net = new Sequential(Optimizer.adam(0.01f),
        Sequential.Loss.SPARSE_CROSS_ENTROPY, 0.05f,   // mild label smoothing
        new Input(7),
        new Dense(16), new ReLU(),
        new Dropout(0.2f),
        new Dense(8), new ReLU(),
        new Dense(2))) {

    net.fit(trainX, trainY, 150, 32, testX, testY, true);
}
  • Label smoothing (0.05) stops the net from pushing probabilities to exactly 0/1 on noisy labels; watch how it keeps the validation loss flat instead of climbing.
  • Dropout(0.2) regularizes the small 2,000-row set; without it the model memorizes noise.
  • Seeded 70/30 split (1,400 / 600) after a seeded shuffle keeps runs reproducible.

Evaluation: Highlighting Churn Recall

Metrics.printReport(loss, acc, conf, {"stays", "churns"}) prints per-class metrics. Because churners are the minority (~10%), the arg-max cut-off P(churn)≥0.50 catches only obvious cases:

Accuracy:        0.89
class         precision    recall        f1  support
stays            0.92        0.97       0.94     544
churns           0.33        0.16       0.22      56

threshold P(churn)>=0.50 -> churn recall=0.16 precision=0.33
threshold P(churn)>=0.35 -> churn recall=0.46 precision=0.31
threshold P(churn)>=0.25 -> churn recall=0.59 precision=0.26

This is exactly how retention campaigns work in practice: nobody needs a hard 0.5 verdict - they call the top-N riskiest customers. Lowering the threshold trades some precision for much better recall, and the program prints this sweep automatically. It also scores three brand-new customer profiles so you can see the learned formula in action (short tenure + expensive month-to-month → high P(churn)).

Exercises
