Tutorial 4 - MNIST Digit Classification with a CNN

Project Overview

Classify handwritten digits (0-9) from 28×28 grayscale images using a small convolutional neural network. MNIST is the classic computer-vision starter dataset: 60,000 training images and 10,000 test images of digits written by census employees and high-school students. This project shows how convolution and pooling extract shape features, why a CNN beats a plain MLP on images, and how to keep the whole thing running in well under a minute on CPU.

The Dataset

MNIST ships in the original IDX binary format, gzip-compressed. The project reads the four files directly with IdxDataset.loadImages / loadLabels:

train-images-idx3-ubyte.gztraining images60000 × 28 × 28
train-labels-idx1-ubyte.gztraining labels 0..960000
t10k-images-idx3-ubyte.gztest images10000 × 28 × 28
t10k-labels-idx1-ubyte.gztest labels 0..910000

The default data directory is C:\Users\dell\Desktop\data\mnist; pass another directory as the first program argument if your files live elsewhere.

Data Preparation

Only one preparation step is needed - pixel normalization:

float[] trainX = IdxDataset.normalize(trIm.pixels());   // bytes 0..255 -> floats 0..1

Dividing by 255 puts every input in [0,1]. Small, similarly-scaled inputs keep the gradient magnitudes even across layers, so Adam's learning rate of 0.001 works for every weight at once. Note that labels arrive as unsigned bytes and are widened with & 0xFF before training.

Model Architecture

Input4D(28,28,1)
  └─ Conv2D(16,3x3, stride 1, SAME), ReLU      learns edges and strokes
       MaxPool2D(2x2, stride 2, VALID)          halves the map
  └─ Conv2D(32,3x3, stride 1, SAME), ReLU      learns digit-part combinations
       MaxPool2D(2x2, stride 2, VALID)
  └─ Flatten                                    7×7×32 = 1568 values
  └─ Dense(128), ReLU, Dropout(0.25)            classifier head
Dense(10)                                       one score per digit

Why a CNN beats an MLP on images

  • Local connectivity - a 3×3 filter looks at neighboring pixels where the visual information lives; an MLP's dense weights connect every pixel to everything and must relearn shift relationships from scratch.
  • Parameter sharing - the same 16 filters slide across all 784 positions, so a stroke detector learned in the corner also works in the center. This first conv layer holds only 16×(3×3)+16 = 160 weights instead of tens of thousands.
  • Translation tolerance - pooling summarizes each neighborhood, so small shifts of the digit barely change the pooled features.

Spatial math: SAME convolutions and stride-2 pooling

SAME padding pads the input with zeros so a stride-1 3×3 convolution keeps the width and height unchanged. Each 2×2 pool with stride 2 then halves both dimensions:

28x28x1  -> Conv SAME 3x3  -> 28x28x16 -> MaxPool 2x2 s2 -> 14x14x16
         -> Conv SAME 3x3  -> 14x14x32 -> MaxPool 2x2 s2 ->  7x7x32
Flatten  -> 1568 features -> Dense(128) -> Dense(10)

VALID pooling on an even-sized map is exact (no dropped rows/columns), which is why the chain is clean at every step.

Training Code Walkthrough

try (Sequential net = new Sequential(Optimizer.adam(0.001f),
        new Input4D(28, 28, 1),
        new Conv2D(16, 3, 3, 1, 1, Padding.SAME), new ReLU(),
        new MaxPool2D(2, 2, 2, 2, Padding.VALID),
        new Conv2D(32, 3, 3, 1, 1, Padding.SAME), new ReLU(),
        new MaxPool2D(2, 2, 2, 2, Padding.VALID),
        new Flatten(),
        new Dense(128), new ReLU(),
        new Dropout(0.25f),
        new Dense(10))) {

    net.fit(trainX, trainY, epochs, batchSize, testX, testY, true);
}
  • Adam(0.001) - the canonical starting rate for CNNs; higher rates oscillate because conv gradients are noisier than dense ones.
  • Dropout(0.25) after the hidden Dense layer randomly zeroes a quarter of its units during training only, delaying overfitting.
  • Data layout - flat row-major float arrays: 60,000 × 784 = 47M floats for the training images.
  • Command line - args[0] args[1] args[2] override datadir, epochs (default 3) and batch (default 128); flags like --epochs 1 also work for quick checks.

Evaluation

After 3 epochs (about 40 seconds on CPU) the network reaches:

Epoch 3/3 - loss: 0.0518 - val_loss: 0.0414 - val_acc: 0.9854

Accuracy:        0.9854          <- 9854 / 10000 test digits correct

The 10×10 confusion matrix (conf[true][predicted]) shows which digits get mixed up - typically 4/9, 3/5 and 7/2 dominate, exactly the pairs humans also misread. Even a single epoch already clears 98%:

--epochs 1  ->  Accuracy: 0.9803
--epochs 3  ->  Accuracy: 0.9854

The project also prints ten textual sample predictions straight from net.predict(testX), e.g. image 0: true=7 predicted=7 confidence=1.000 OK.

Model Persistence

net.saveTo(Path.of("target", "mnist-cnn-model.bin")) stores the layer spec plus weights; reload later with Sequential.loadFrom(path, Optimizer.adam(0.001f)) without retraining.

How to Run

Exercises

  1. Add a third Conv2D(64,...) block - how much accuracy do you gain per extra second of training?
  2. Replace both MaxPool layers with strides of 2 in the convolutions itself - compare speed and accuracy.
  3. Raise the learning rate to 0.01 - does the loss curve become unstable?
  4. Remove IdxDataset.normalize(...) and train on raw 0..255 pixels - how badly does convergence suffer?
