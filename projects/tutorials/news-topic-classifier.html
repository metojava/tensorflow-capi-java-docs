Tutorial 13 - News Topic Classification

Project Overview

This is the library's deep-dive into classic NLP: classify a headline into one of four topics (sport / tech / weather / finance). Unlike Tutorial 7's two-class sentiment model, here you build the whole pipeline - vocabulary, token ids, padding - over a larger generated corpus, and then train two competing architectures on identical data to see where each wins.

Synthetic Corpus

The seeded generator (seed 42) produces 1,600 headlines by shuffling 2–4 topic keywords among 3–6 neutral filler words:

Topic (label)Keyword examples
sport (0)goal, striker, league, cup, penalty, stadium...
tech (1)chip, startup, cloud, quantum, algorithm, server...
weather (2)storm, heatwave, blizzard, humidity, floods...
finance (3)stocks, inflation, earnings, merger, currency...
"small local cup tournament stadium new"

Fillers (the, city, officials, warns, week...) carry no topic signal, so the models must learn which words matter - exactly what embeddings are for.

NLP Pipeline Done Right

  1. Seeded split first: Datasets.trainTestSplit(1600, 0.2, 7L) → 1,280 train / 320 test (train size is a multiple of batch 32).
  2. Vocabulary from TRAIN tokens only. Building the word-to-id map on all text would let test-set words shape the encoding - a subtle leak. Unseen test words become <UNK>.
  3. Encode to fixed length T=10: ids 0 = UNK, 1 = PAD, real words from 2 up, sorted by descending frequency; truncate or right-pad every headline.
"small local cup tournament stadium new"
   -> [5,17,58,40,50,12,1,1,1,1]

Two Architectures, One Dataset

A key constraint of this library shapes the design: the Embedding layer outputs a flattened [T*embDim] vector per sentence, so it feeds Dense heads; recurrent layers instead read raw [batch, T, D] flows - so they take one-hot token planes (D = vocabSize).

Model A - Embedding bag-of-wordsModel B - order-aware LSTM
InputInput3D(T,1), token ids as floats Input3D(T,V), one-hot planes (T×V floats)
BodyEmbedding(V,16) → Dense(32) → ReLU → Dropout(0.2) LSTM(24) → Dense(32) → ReLU
Word order?ignored (bag-of-words)read step by step
Costvery cheapT× more compute + unrolled BPTT
// Model A
try (Sequential net = new Sequential(Optimizer.adam(0.01f), 42L,
        new Input3D(T, 1),
        new Embedding(vocabSize, 16),
        new Dense(32), new ReLU(),
        new Dropout(0.2f),
        new Dense(4))) { ... }

// Model B
try (Sequential net = new Sequential(Optimizer.adam(0.01f), 43L,
        new Input3D(T, vocabSize),
        new LSTM(24),
        new Dense(32), new ReLU(),
        new Dense(4))) { ... }

Both train with EarlyStopping.valLoss(20, true) and seeded shuffling. In the default run Model A stops itself at epoch 51/150 while the LSTM uses its full budget - the embedding baseline converges faster on this much vocabulary repetition.

Evaluation

With disjoint keyword vocabularies the task is linearly separable, so both reach perfect held-out accuracy (supports 71/86/70/93):

Confusion matrix (rows = true label, columns = predicted):
             0     1     2     3
  0         71     0     0     0
  1          0    86     0     0
  2          0     0    70     0
  3          0     0     0    93

Test accuracy: embedding-bag 1.000 | lstm 1.000

The interesting comparison is cost at equal quality: when a cheap bag-of-words matches the recurrent model, ship the cheap one. The LSTM earns its keep once word order or shared words start to matter - see the exercises.

Exercises

  1. Add ambiguous shared keywords ("market" in finance AND tech, "match" in sport AND tech) - does the gap between bag-of-words and LSTM appear?
  2. Swap LSTM(24) for GRU(24) - compare epochs-to-converge and accuracy.
  3. Cut the training set to 200 headlines - which architecture degrades faster, and why?
  4. Reduce T to 5 (truncate harder) - how much information can you lose before accuracy drops?
  5. Try to stack Embedding → LSTM. Read the Embedding javadoc first: why is it impossible with the current layer, and what would a sequence-preserving Embedding need to return?
  6. Negation compositionality: add examples where "not X" flips meaning. Can either architecture learn the flip from a handful of cases?
