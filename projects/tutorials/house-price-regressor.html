Tutorial 11 - House Price Regression

Project Overview

Where Tutorial 3 bucketed houses into cheap/medium/expensive bands, this project predicts the exact sale price. That is regression proper: a continuous target, a mean-squared-error objective and error metrics expressed in dollars. It is also a tour of the library's training controls - seeded reproducibility, a cosine learning schedule, decoupled weight decay, gradient clipping and EarlyStopping deciding when to stop.

Synthetic Dataset

The seeded generator (seed 42) creates 1,600 houses with six features and a ground-truth pricing formula:

FeatureRangeEffect on price
sqft500..3500+120 per sqft
bedrooms1..6+8,000 each
age0..80-900 per year
locationScore1..10+15,000 per point
garageSpaces0..3+12,000 each
distanceToCenter0.5..30 km-2,500 per km
price = 120*sqft + 8000*bedrooms - 900*age + 15000*location
      + 12000*garage - 2500*distance + 8*sqft*location
      + noise(N(0, 25000))
price = max(price, 50000);   // clip unrealistic lows

The new ingredient versus Tutorial 3 is the interaction term 8*sqft*location: a square foot is worth far more in premium districts. A linear model cannot represent that product; the MLP learns it implicitly through its hidden layers, which is exactly the kind of structure regression networks are for.

Pipeline

  1. Generate 1,600 rows with seed 42.
  2. Datasets.trainTestSplit(1600, 0.3, 42L), then materialize both splits with Datasets.gatherRows/gatherFloats (1,120 train / 480 test).
  3. Standardize the six features with train-split statistics only (fitStandardizer + applyStandardizer).
  4. Standardize the target too: fit z-score parameters of the train prices and transform both splits. The network then learns prices as unit-less residuals, which converges much faster than raw dollars.
// after training, predictions come back to dollars:
double pred = predZ[i] * yStd + yMean;

The split sizes are deliberately multiples of the batch size (32) so every training batch is full - the trainer feeds pre-packed batch buffers and expects uniform shapes.

Model and Regularized Optimizer

Optimizer opt = Optimizer.adam(0.01f);
opt.setWeightDecay(1e-4f);     // decoupled (AdamW-style) decay
opt.setGradClipNorm(5f);       // safety net against gradient spikes

try (Regressor net = new Regressor(opt, SEED,
        new Input(6),
        new Dense(64), new ReLU(),
        new Dense(32), new ReLU(),
        new Dense(1))) {

    net.setShuffleSeed(SEED);
    net.setLrSchedule(LrSchedule.cosine(epochs, 0.01f));

    EarlyStopping es = EarlyStopping.valLoss(25, true);
    Regressor.RegressionHistory h =
            net.fit(trainX, trainY, epochs, 32, testX, testY, true, es);
}

Notes on each control:

  • Seeds everywhere: seed 42 fixes weight init (constructor) and batch order (setShuffleSeed) - reruns are identical.
  • Cosine schedule: the effective rate glides from 100% down to 1% of 0.01 across the requested epochs - big steps early, fine adjustments late.
  • Weight decay pulls weights toward zero each step; harmless here, valuable when datasets get smaller.
  • Gradient clipping at global norm 5 costs nothing normally but caps any pathological batch.

Early Stopping in Action

EarlyStopping.valLoss(25, true) watches validation MSE and stops after 25 epochs without improvement, restoring the best weights seen. In the default run it fires at epoch 59:

Epoch 33/300 - loss: 0.01820 - val_loss: 0.02806
Epoch 34/300 - loss: 0.02008 - val_loss: 0.02277   <- best
Epoch 35/300 - loss: 0.01788 - val_loss: 0.02836
...
Epoch 57/300 - loss: 0.01649 - val_loss: 0.02291
Epoch 58/300 - loss: 0.01852 - val_loss: 0.02757
Epoch 59/300 - loss: 0.01836 - val_loss: 0.02358
Early stopping at epoch 59 - best val_loss 0.02277 at epoch 34
Ran 59/300 epochs - best val MSE 0.02277 at epoch 34

We budgeted 300 epochs; the callback returned 241 of them. Because restoreBestWeights=true, the saved model is the best one seen, not the overtrained final one.

Evaluation

Predictions are de-standardized back to dollars before scoring. Expected result:

RMSE $26,755 | MAE $21,538 | R^2 0.975

     actual      predicted
 1) $  409,497  $  415,319
 2) $  482,890  $  477,756
 3) $  209,739  $  220,401
 4) $  194,539  $  190,124
 5) $  330,013  $  334,775
 6) $  226,358  $  217,541

The injected pricing noise has σ = $25,000, so an RMSE of ~$27k means the model has learned essentially everything learnable - the residual is the noise itself. R² = 0.974 says 97.4% of test price variance is explained. Compare Tutorial 3's classifier: same market, coarser question, easier task.

Exercises

  1. Increase the noise σ to 50,000 - watch RMSE track it while R² stays high. Which metric tells the truer story?
  2. Delete the interaction term from the generator and retrain: how much easier does the task get?
  3. Remove target standardization (train on raw dollars) and compare epochs-to-converge.
  4. Set patience to 3 - does stopping too early cost accuracy? Then try 100 - does it ever help?
  5. Skip opt.setGradClipNorm and raise the base LR to 0.1 until training diverges; reinstate clipping and observe the rescue.
