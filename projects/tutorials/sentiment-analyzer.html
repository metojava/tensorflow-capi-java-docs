Tutorial 7 - Sentiment Analyzer with Embeddings

Project Overview

Classify short movie reviews as positive or negative. Instead of downloading a corpus, this project hand-curates 80 one-line reviews directly in code (40 positive, 40 negative) so every step - tokenizing, building the vocabulary, encoding text to numbers - is visible and reproducible. The model learns a trainable word-embedding table and classifies reviews from it.

The Corpus and the Vocabulary

Sentiment-bearing words (wonderful, brilliant, terrible, boring ...) are deliberately reused across many sentences so a classifier can actually learn them from ~64 training examples; filler words add vocabulary variety (178 distinct words in total). Every word is mapped to an integer id:

IdMeaning
0<UNK> - any word never seen while building the vocabulary
1<PAD> - padding used to fill short sentences
2..Vcorpus words sorted by descending frequency (ties alphabetical)

Encoding: Fixed-Length Token Sequences

A neural net needs fixed-size inputs, but sentences have different lengths. Each review is lowercased, stripped of punctuation, split on whitespace and then encoded to exactly T = 12 token ids:

  • Truncation - longer sentences keep only their first 12 tokens.
  • Padding - shorter sentences are right-padded with PAD = 1.
"a dull unfunny movie with bad dialogue" -> [ 34  9 77  5 41 88   1   1   1   1   1   1 ]

Embeddings vs one-hot encoding

Two ways to turn id 41 into something a Dense layer can use:

  • One-hot vector - length V (=180 here) with a single 1. Huge, sparse, and every word is exactly as different from every other word.
  • Embedding row - a learned dense vector of size 16 from a [V, 16] table. Words that behave similarly drift toward similar vectors during training, which is what generalizes across sentences.

Lookup-as-one-hot-matmul note: mathematically, picking row i of table E equals multiplying the one-hot vector of i by E. The library realizes the lookup exactly that way - onehot(ids) @ E[vocab,16] - because its gradient is a plain dense tensor that the generic TF_AddGradients path handles without IndexedSlices conversion. That is also why the embedding ids are fed as floats through an Input3D(T,1) flow and cast to int32 inside the graph.

Model Architecture

Input3D(12,1)
Embedding(vocabSize=180, 16)     lookup table, output flattens to [batch, 12*16=192]
Dense(16), ReLU                  classifier head
Dropout(0.2)
Dense(2)                         negative / positive scores

The Embedding output for one review is the concatenation of its 12 word vectors - a 192-value vector - so the following Dense layers see ordinary tabular data.

Training Code Walkthrough

try (Sequential net = new Sequential(Optimizer.adam(0.02f),
        new Input3D(T, 1),
        new Embedding(vocabSize, 16),
        new Dense(16), new ReLU(),
        new Dropout(0.2f),
        new Dense(2))) {

    net.fit(trainX, trainY, 250, 16, testX, testY, true);
}
  • 80/20 seeded split - indices are shuffled once with seed 42: 64 reviews train, 16 measure generalization.
  • 250 epochs × batch 16 - only 4 gradient steps per epoch; the whole run takes seconds. Training loss reaches ~0 quickly, which is normal on tiny corpora.
  • Data layout - flat arrays: 64 rows × 12 ids = 768 floats.

Evaluation

Held-out accuracy lands between 75% and 88% depending on the shuffle (the library's per-epoch shuffle is intentionally unseeded), clearly above the 69% majority-class baseline for this split:

Model Persistence

net.saveTo(Path.of("target", "sentiment-model.bin")) stores the architecture spec, vocabulary-independent weights included; reload with Sequential.loadFrom(path, Optimizer.adam(0.02f)). Keep the vocabulary map alongside the file - without it you cannot tokenize new sentences the same way.

Exercises

  1. Add 10 new reviews of your own - does accuracy improve more if they reuse existing marker words or introduce new ones?
  2. Raise T to 16 and re-pad - what changes for short sentences?
  3. Increase embDim to 32 with only ~180 words - earlier overfitting or better generalization?
  4. Print the learned embedding rows of "wonderful", "great" and "terrible" - do positive words cluster together?
