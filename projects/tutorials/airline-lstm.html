Tutorial 8 - Airline Passengers with an LSTM

Project Overview

The classic airline-passengers dataset records monthly international passenger counts from 1949 to 1960 (144 points). Instead of forecasting the exact count, this project predicts the direction of the next month-over-month change: up if p[t+1] > p[t], otherwise down. That turns the series into a binary classification problem - 143 examples - solved with an LSTM that reads a short window of recent changes.

From Time Series to Supervised Examples

The raw series is transformed twice:

  1. Deltas - delta[i] = p[i+1] - p[i], giving 143 month-over-month changes. Deltas remove the strong upward trend and center the problem on what we actually want to predict.
  2. Sliding windows - example t is the six values delta[t-5..t] packed into a sequence of shape [6,1]; its label is the sign of delta[t]. Early examples repeat their oldest available delta instead of going out of bounds.
deltas:   +6  +14 +(-3) +(-8) +14 ...          <- 143 values
window t=9: [+14, -8, +14, +13, +12, +9] -> label: up

Each delta is standardized as (d - mean) / std using statistics from the training period only (mean 2.43, std 23.47), exactly like the tabular projects standardized their feature columns.

Why the Chronological Split Matters

Tabular projects shuffled rows before splitting. A time series must not be shuffled: the future may not leak into training. The first 100 examples (roughly 1949 through mid-1958) train the model; the last 43 are held out for testing. Shuffling would let the network peek at later years' patterns and report inflated accuracy.

A Majority Baseline Keeps You Honest

Before trusting any model, check what the dumbest reasonable strategy scores. "Always predict the majority class seen in training" (up) reaches 58.1% on the test period because airlines grew most months. Any real model must beat that number - a network scoring below it has learned nothing useful.

The LSTM Layer in Brief

A vanilla RNN's hidden state tends to forget or explode over long sequences. An LSTM adds a cell state guarded by three gates computed at every step:

  • Forget gate f = sigmoid(...) - how much of the old cell state survives.
  • Input gate i = sigmoid(...) - how much of the new candidate enters.
  • Output gate o = sigmoid(...) - how much of the cell state is revealed.
c = f ⊙ c' + i ⊙ tanh(candidate)      h = o ⊙ tanh(c)

The additive update lets gradients flow across many steps unchanged, which is what "long short-term memory" refers to.

Model Architecture

Input3D(6,1)
LSTM(8)                    unrolled over T=6 steps, output flattens to [batch, 6*8=48]
Dense(16), ReLU
Dense(2)                   down / up scores

The LSTM emits all per-step hidden states concatenated - [B, T*H] = [B,48] here - so the Dense layers afterwards see ordinary flat data, just like the Embedding layer did in the sentiment project.

Training Code Walkthrough

try (Sequential net = new Sequential(Optimizer.adam(0.01f),
        new Input3D(WINDOW, 1),
        new LSTM(8),
        new Dense(16), new ReLU(),
        new Dense(2))) {

    net.fit(trainX, trainY, 200, 16, testX, testY, true);
}
  • No shuffle anywhere - fit() shuffles batch order internally, which only permutes whole training examples within the train period and does not move rows across the split boundary.
  • 200 epochs × batch 16 - 7 steps per epoch over 100 training windows; finishes in seconds on CPU.
  • Data layout - flat arrays: 100 rows × 6 deltas = 600 floats for training.

Evaluation

Validation accuracy climbs within a handful of epochs and stabilizes far above the baseline:

Majority baseline (train class=up): test accuracy 0.581 (25/43)
Epoch 200/200 - loss: 0.0000 - val_loss: 0.2354 - val_acc: 0.9767

Accuracy:        0.9767          vs baseline 0.581

Confusion matrix (rows = true label):
             0     1
  0         18     0       down: recall 1.000
  1          1    24       up:   recall 0.960

One honest caveat: the most recent delta in each window already hints at its own sign, so part of this lift comes from reading the last input step rather than from long-range memory. That is exactly why the tutorial reports the majority baseline - it separates "the task is easy" from "the model is good". Try removing the last window element (use delta[t-5..t-1]) to see how much harder true one-step-ahead prediction becomes.

Model Persistence

net.saveTo(Path.of("target", "airline-lstm-model.bin")) stores the unrolled LSTM spec plus weights; reload with Sequential.loadFrom(path, Optimizer.adam(0.01f)).
