Tutorial 1 - Iris Flower Classification

Project Overview

Predict the species of an iris flower (setosa, versicolor, or virginica) from four physical measurements. This is the "Hello World" of machine learning: a small dataset (150 rows), a simple multi-layer perceptron, and a complete end-to-end workflow - data loading, feature scaling, train/test splitting, training, evaluation and model saving.

The Dataset

Fisher's Iris dataset ships with the project at src/main/resources/data/iris.data. Each row holds four measurements (centimeters) followed by the species label:

5.1,3.5,1.4,0.2,Iris-setosa
6.7,3.1,4.4,1.4,Iris-versicolor
6.3,3.3,6.0,2.5,Iris-virginica

Data Preparation

Three preparation steps matter even on this tiny dataset:

  1. Seeded shuffle - the CSV is grouped by species, so we shuffle indices with a fixed seed (42) before splitting to get all three classes into both sets while keeping results reproducible.
  2. 105 / 45 split - 70% of rows train the network, 30% measure how well it generalizes to flowers it has never seen.
  3. Z-score standardization - each feature is transformed to (value - mean) / std. The statistics come from the training set only; applying them to the test set prevents information leaking from the future. Unscaled inputs slow convergence because gradient descent must find very different step sizes per dimension.

Model Architecture

Input(4)
  └─ Dense(16), ReLU      hidden layer: learns feature combinations
Dense(3)                    output layer: one score per class

With only 4 inputs, 16 hidden units are plenty. The last layer has exactly numClasses = 3 units because Sequential reads the class count from it and trains with sparse softmax cross-entropy over integer labels.

Training Code Walkthrough

The whole model fits in a few lines:

try (Sequential net = new Sequential(Optimizer.adam(0.01f),
        new Input(4),
        new Dense(16), new ReLU(),
        new Dense(3))) {

    History h = net.fit(trainX, trainY,   // flat [rows*4] features, int[] labels
                        150, 16,          // epochs, batch size
                        testX, testY,     // validation split
                        true);            // print one line per epoch
}

Key points:

  • Adam(0.01) adapts per-parameter learning rates; on small tabular problems it converges faster than plain SGD.
  • Data layout - tensors are flat float[] arrays in row-major order; 105 samples × 4 features = 420 floats.
  • fit() shuffles every epoch, slices mini-batches of 16, runs a forward pass, computes gradients natively via TF_AddGradients, applies the optimizer, then evaluates on the validation set.

Evaluation

We fetch class probabilities with net.predict(testX) (returns 45×3 floats), take the arg-max per row, and accumulate a confusion matrix that Metrics.printReport turns into accuracy, precision/recall/F1 per class:

int pred = Metrics.argmax(probs, i * 3, 3);
conf[testY[i]][pred]++;               // conf[true][predicted]

Expected result after 150 epochs (exact numbers vary slightly by platform):

Accuracy:        0.93
Confusion matrix (rows = true label):
             0     1     2
  0          8     0     0      setosa perfectly separated
  1          0    14     1
  2          0     2    20

Setosa is linearly separable from the other two species, so it always scores 100%. Versicolor/virginica overlap slightly, which is where the few mistakes appear - exactly what the confusion matrix visualizes.

Model Persistence

net.saveTo(Path.of("target", "iris-model.bin")) writes the architecture spec plus weights. Reload later without retraining:

Sequential net = Sequential.loadFrom(Path.of("iris-model.bin"),
                                     Optimizer.adam(0.01f));

Exercises

  1. Remove standardization and compare the loss curve - how much slower does it converge?
  2. Change the seed in seededOrder(n, 42) - how stable is test accuracy across splits?
  3. Add a second hidden layer Dense(8), new Tanh() - does it help or overfit?
  4. Train with Sequential.Loss.SOFTMAX_MSE instead of cross-entropy and compare.
